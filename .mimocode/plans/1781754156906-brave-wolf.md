# 实施计划：安全修复 + 功能补全

## 范围

基于项目审查报告，分两个阶段实施：

### 阶段一：安全修复（server + admin）

#### 1.1 .env 安全加固
- **server/.env** — 确认 `.gitignore` 已排除 `.env`，移除已跟踪的 .env
- **server/.env.example** — 保持模板，密码用占位符

#### 1.2 角色权限控制
- **server/app/middleware/auth.js** — 扩展 JWT payload，检查 `role` 字段
- **server/app/router.js** — 部分路由加 `adminOnly` 中间件
  - 仅 admin 可访问：`/inventory/import`、`/orders/:id/cancel`、`/orders/:id/revert`
  - operator 可访问：订单查看、扫码提交、导出

#### 1.3 清理未使用依赖
- **server/package.json** — 移除 `nanoid`、`safe-stable-stringify`

### 阶段二：功能补全（admin）

#### 2.1 用户管理页面
- **新增** `admin/src/pages/users/index.tsx` — 用户列表（ProTable）
- **新增** `admin/src/pages/users/create.tsx` — 创建用户表单
- **新增** `admin/src/services/users.ts` — 用户 CRUD API
- **server** — 新增用户管理接口：
  - `GET /api/users` — 用户列表（admin only）
  - `POST /api/users` — 创建用户（admin only）
  - `POST /api/users/:id/reset-password` — 重置密码（admin only）
- **admin/config/config.ts** — 添加 `/users` 路由

#### 2.2 库存查看页面
- **新增** `admin/src/pages/inventory/index.tsx` — 库存列表（ProTable + 搜索）
- **新增** `admin/src/services/inventory.ts` — 添加 `fetchInventory()` 函数
- **server** — 新增库存列表接口：
  - `GET /api/inventory` — 库存列表（支持按 product_code、status、roll_code 搜索）
- **admin/config/config.ts** — 添加 `/inventory` 路由

#### 2.3 订单列表搜索
- **修改** `admin/src/pages/orders/index.tsx` — ProTable 添加搜索栏（订单号、车牌号、状态筛选）

### 验证方式

1. 启动 server：`cd server && npm run dev`
2. 启动 admin：`cd admin && npm run dev`
3. 测试：
   - 用 operator 角色登录 → 验证无法访问用户管理
   - 用 admin 角色登录 → 验证可访问所有功能
   - 访问库存页面 → 验证列表加载和搜索
   - 访问用户页面 → 验证创建/查看用户
   - 订单列表 → 验证搜索筛选功能
